# Version upgrades: v42 → v43 (Glasswing) and the general pattern

Major Batocera upgrades are routine but not zero-touch: they rename ROM
directories, change the boot-service model, and swap emulators. The v42→v43
upgrade is the worked example; the *shape* of the migration recurs each major
release, so treat the checklist as reusable even when the specific renames differ.

**Always take a full backup first** (see [backup.md](backup.md)). An upgrade is
the single highest-risk routine event.

## ROM directory renames

Old dirs become empty stubs in ES if not cleaned up; content left in the old dir
becomes invisible. v43 renames (old → new):

- `o2em` → `odyssey2`
- `msu-md` → `megadrive-msu`
- `xash3d_fwgs` → `halflife`
- `plugnplay` → `tvgames`
- `astrocde` → `astrocade`
- `bbc` → `bbcmicro`
- `iortcw` → `rtcw`
- `casloopy` → `loopy`

Migration per rename: move any real content (`gamelist.xml`, `media/`, saves)
from the old dir to the new one, then `rm -rf` the old dir. Stubs containing only
an auto-generated `_info.txt` can be deleted outright — Batocera recreates empty
stubs for unused systems on boot.

**General rule:** after any major upgrade, `ls /userdata/roms/` and reconcile
against the previous system list. Anything that "disappeared" is likely a rename,
not a loss — grep the release notes for the old dir name.

## Boot-service model change

`custom.sh` is deprecated in favor of the services pattern. The v43 upgrade
**auto-converts** `/userdata/system/custom.sh` to
`/userdata/system/services/custom_service` on first boot, preserving the script
body. Confirm it converted and still contains your logic:

```bash
SSHB "ls /userdata/system/services/ && grep -c . /userdata/system/services/custom_service"
```

Write new boot logic as a service from now on, not `custom.sh`.

## Emulator swaps

- **Dolphin-Triforce removed** — mainline Dolphin now handles Triforce. Move
  saves: `/userdata/saves/dolphin-triforce/StateSaves/*.s01` →
  `/userdata/saves/dolphin/StateSaves/`, then `rmdir` the old tree.
- **DraStic removed** (NDS) — MelonDS is the path forward.
- **3DS Azahar** — 3DS ROMs must be **decrypted** to run.
- **New systems** may appear (v43 added `cave3rd` / Cave CV1000, plus several
  empty stubs). Note the `cave3rd` directory-name quirk in `batocera-roms`.

## ES settings that changed

`SortSystems` gained a `hardware` value (BY HARDWARE TYPE THEN YEAR) alongside
`alpha`, `manufacturer`, `subgroup`, `releaseYear`, `releaseDate`. If your sort
looks wrong after the upgrade, this is in
`/userdata/system/configs/emulationstation/es_settings.cfg`.

## Post-upgrade checklist

1. **Governor.** Re-check the CPU governor — a v43 build can boot stuck in
   `powersave` every boot. `cat /sys/.../scaling_governor`; if `powersave`,
   apply the re-assert fix from `batocera-tuning`.
2. **Renamed dirs.** Reconcile `ls /userdata/roms/`; migrate content out of
   renamed/stub dirs; delete empty stubs.
3. **Boot service.** Confirm `custom.sh` converted to `custom_service` intact.
4. **Moved saves.** Migrate saves for any swapped emulator (Triforce → Dolphin,
   etc.).
5. **Image variant.** Confirm you're on the right image for the hardware (a
   plain x86_64 desktop/NUC uses the standard image, not a handheld Wayland
   variant).
6. **Launch test.** Actually launch a game from each major system (arcade, a
   cartridge console, a disc system) and confirm it boots. Don't declare the
   upgrade done from the menu appearing — declare it done from games running.
