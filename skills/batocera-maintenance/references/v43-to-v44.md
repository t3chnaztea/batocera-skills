# Version upgrades: v43 → v44 (Malachite)

Read [v42-to-v43.md](v42-to-v43.md) first for the general pattern. This page
lists what was different on one x86_64 cabinet that went from 43.1 to 44.

## The upgrade run

`batocera-upgrade` works over SSH with no terminal attached. Start it detached
with its output in a log file, because the SSH session can drop:

```bash
SSHB 'setsid nohup batocera-upgrade > /userdata/system/logs/upgrade.log 2>&1 &'
```

Wait for the checksum line and exit code 0 in the log. Check that nobody is in
a game (`curl -s http://127.0.0.1:1234/runningGame`), then `reboot`. The boot
partition needs room for the new image next to the old one. Check `df -h /boot`
first.

## ROM directory renames

- `gzdoom` → `uzdoom` (the engine changed too). Move the WADs, `gamelist.xml`,
  `images/` and `videos/`. The emulator starts a new config directory at first
  launch. Settings in the old `configs/gzdoom/` do not carry over.
- `traider1` and `traider2` → `traider`.

## Emulators replaced

A system that keeps its name can still get a different emulator. The ROM sets
and the per-system keys that worked before may not fit the new one.

- **Sega Model 2:** a native emulator replaces the Windows one that ran under
  Wine. It wants current MAME set names and complete parent sets. Sets built
  for the old emulator fail at launch or start with missing graphics.
- **Namco System 246/256:** a PCSX2 fork replaces the earlier emulator. The
  games are loader files that name a dongle image and a disc image, so a game
  needs all three files. Missing dongle files give a boot error screen, not a
  crash.
- **Atari 5200:** the dedicated libretro core is gone and the Atari 800 core
  runs the system. Existing `.a52` files and the BIOS worked without changes.

Treat each replaced emulator as a new system: launch every game you keep
visible, look at a screenshot, and hide what fails. `batocera-ops` has a batch
launch test script for this.

## Smaller changes

- Files in `/userdata/system/services/` that are not valid service names (for
  example `custom_service.bak-2026`) now print a warning at boot and in
  `batocera-services list`. They are skipped, not run. Keep backups of service
  files in another directory.
- v44 sets the performance CPU governor by default. A boot-time governor
  override from the v43 workaround is now harmless and can stay.
- The upgrade rewrote a few commented default lines in `batocera.conf`. Diff
  the file against your pre-upgrade copy and expect only that.
- Picture placement inside bezels that have no `.info` file changed upstream.
  Re-check any bezel fit work done on v43 with a launch and a screenshot.
